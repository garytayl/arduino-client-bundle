What we verified on the bench

The combined sketch was compiled and uploaded on October 24. Live serial confirmed movement detection, clear rearming and effect completion. LEDs worked after correcting the input end and repairing contacts. The current effect is a continuous spectrum rainbow with a sparkling ripple from the center toward both ends.

The final refinement has smoother color blending and a 32-second rainbow cycle. State tests cover valid-only debounce, rearming, invalid and stale readings, sampling gaps and timer wrap. Renderer tests cover symmetry and propagation. The physical LED count is still an estimate; 90 is the configured count.

Not yet tested: multi-sensor operation, directional detection, installed cable runs, permanent mounting or a finished power system. One sensor currently detects presence, not travel direction.

01 / NEXT VISIT

Get four to five sensors
working with the LEDs.

This is the chosen prototype goal. We’ll add sensors one at a time, then test them as a group before moving on to installation planning.

  1. Set up the multiplexer bench.

    Label the sensors 1–5. Use one VL53L1X per TCA9548A channel. Verify the actual carrier supply, logic levels and connectors, then select and initialize each channel independently.

  2. Connect the sensing to the lights.

    Build a separate mux-aware firmware version. Confirm each channel’s reading and LED response, clear/rearm behavior and repeated cold boots. The current downloadable sketch supports one sensor directly on Wire.

  3. Prove the complete group.

    Run all 4–5 sensors with LEDs active. Check timing, overlapping views, false or missed detections, lingering presence, invalid readings and recovery. Agree the trial count and record actual results.

Ready to move on when: every intended channel works after restart, readings stay attributable to the right sensor, and repeated approaches produce the intended LED behavior without false triggers.
Decisions and measurements to capture that day

Choose whether the final behavior needs presence, ordered travel direction or individual step coverage. Survey tread count, widths, riser heights, landing geometry, sightlines, mounting depth and cable routes. Confirm the real strip count and specification. Keep household measurements in the on-site notes, not the public guide.

Selecting a mux channel does not stop other powered sensors from ranging optically. Compare isolated and grouped operation; validate staggered measurements if needed, polling latency, ambient-light changes, target differences and simultaneous traffic.

03 / THE CONNECTION PLAN

One controller.
Separate sensor channels.

The multiplexer is the chosen splitter. It separates sensors with the same address. This is a conceptual bench topology, not a verified terminal-by-terminal installation drawing.

The signal path

UNO main SDA/SCL → TCA9548A → one sensor per channel.

Use CH0–CH3 for four sensors and CH4 for the optional fifth. Each sensor stays at address 0x29; the mux defaults to 0x70. Firmware selects exactly one channel before configuring or reading that sensor.

Never enable several same-address sensor channels at once. Keep readings and presence state separate for each sensor.

Power and ground

A verified regulated sensor rail feeds the carriers. Ground is shared between UNO, mux and sensors. Check the group’s load before deciding whether the controller rail can power it.

LED 5 V supply → appropriate fused distribution → strip power and planned injection points. D6 → series resistor → first DIN, with a shared signal ground. Strip current never passes through the UNO or a breadboard.

The diagram does not connect the external LED +5 V to the USB-powered UNO +5 V.

Short bench first. Real routes next.

A mux is not a long-cable extender. Measure the proposed sensor routes and test the intended cable lengths, bus pull-ups, capacitance and rise time before hiding anything.

Controller location, branch lengths, exact pin assignments and permanent connector choices remain TBD. Revise the topology if raw I²C cannot meet timing over the measured route.

Electrical compatibility and manufacturer references

Adafruit’s mux pinout guide specifies matching VIN to host logic for a 5 V Arduino and states that downstream channel pairs have no pull-ups installed. Inventory the sensors’ existing pull-ups and rail levels before adding anything. TI’s device documentation describes the eight selectable channels.

The CQRobot CQRWX00744US manual specifies 3.3 V/5 V operation and onboard voltage translation. Match the actual carrier revision and labels; this does not prove every signal pin is 5 V tolerant. The proposed combination still needs an end-to-end UNO R4 bench test.

The mux plan does not need XSHUT address sequencing. Do not assume 5 V on SHUT/INT. Pololu’s carrier documentation warns its XSHUT is not 5 V tolerant; its schematic is not a substitute for CQRobot’s. A shared-bus address-assignment alternative would require individually controlled startup after each reset.

NXP’s I²C specification is the basis for bus timing and capacitance checks. There is no universal cable length prescribed here. A buffered/differential link or local-controller redesign may be needed after testing.

04 / AFTER THE SENSOR BENCH

Make it fit.
Keep it serviceable.

Installation planning starts after the multi-sensor bench succeeds. Nothing is mounted or approved for permanent installation yet.

Placement

Mock up before fixing.

Choose sensor sightlines, LED channels and diffusers, removable mounts and an accessible controller enclosure. Test any sensor cover window; keep apertures unobstructed.

Hidden wiring

Hide it without trapping it.

Measure a protected route with labelled connectors, strain relief and service slack. Keep junctions reachable and surfaces clear of foot-contact or snagging hazards.

Electrical design

Size for the actual load.

Use the real strip specification and measured runs to choose supply capacity, wire gauge, branch fusing and injection. Check far-end voltage drop under the intended worst-case pattern. Brightness 16 is a bench setting, not wiring protection.

Pilot

Install a small section. Walk it.

Approve a reversible pilot, then repeat traffic, lingering, ambient-light, restart and failure tests in the actual positions. Expand only after agreed criteria pass.

Power reference: Adafruit’s NeoPixel power guide. Final ratings and quantities follow the measured design; no additional order is implied.
