ONE MODULE / FOUR WIRES

  1. Power off first. Unplug USB and the LED adapter. Disconnect the LED strip and all other modules from this test. Confirm the CQRobot translated carrier and its printed pin labels; do not infer pin order from cable colors.
  2. Wire only the documented carrier connections, while off. VCC → UNO 5V, GND → GND, SDA → main SDA, SCL → main SCL. Leave INT and SHUT unconnected and insulated. Use the main SDA/SCL headers, not the Qwiic connector. Recheck labels before USB-only power; leave the LED adapter unplugged.
  3. Install the matching library. In Arduino IDE Library Manager, install VL53L1X by Pololu, version 1.3.1. Do not substitute VL53L0X. Select Arduino UNO R4 WiFi in the Arduino UNO R4 Boards package. Open this file in its own VL53L1X_ToF_Bench_v1 folder and verify it.
  4. Choose before replacing a program. Save the current sketch. Only if Gary chooses to replace the board’s running program, select the correct board/port and upload this standalone diagnostic. No upload or hardware access has been performed here.
  5. Observe at 115200 baud. Look for VL53L1X_TOF_BENCH_V1. The sketch checks address 0x29 and model ID 0xEACC. If it reports not found, mismatch or timeout, stop and power off before checking wiring. Do not force the driver or swap to VL53L0X to bypass a mismatch.
  6. Try a flat target indoors. Start about 20–50cm in front, then move it and compare. Numeric output is millimetres only for RangeValid; other measurements show NA and a status. Record observations before claiming range or a staircase pass.

CARRIER TRANSLATION MATTERS

5V carrier ≠ 5V bare chip.

The matched carrier manual documents 3.3V/5V operation and an onboard voltage translator. These four-wire instructions depend on that carrier identification. They do not apply to an unidentified board or bare VL53L1X chip.

No 5V tolerance is established for INT/SHUT; keep them disconnected. This is distinct from the HW-870 reflectance modules.

WHAT THIS DIAGNOSTIC DOES

Read ranges. Report faults.

Pololu 1.3.1 declares all Arduino architectures; its Wire calls were checked against the UNO R4 Renesas core. This is API review, not a successful board compile.

The sketch uses normal volatile sensor initialization/ranging/acknowledgement, a 50ms timing budget, 100ms ranging period, readiness polling and timeouts. It does not change the address, request custom calibration or control LEDs, motors or Wi-Fi. After a fault it makes no further bus calls; the sensor may keep ranging until powered off.
