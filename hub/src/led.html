BEFORE CHOOSING TO RUN IT

  1. Power off USB and adapter before checking connections. Confirm the actual strip DIN/arrow and its labeled 5V/GND polarity. Gary now confirms the DIN label at the connected end; polarity and the complete wiring are not independently verified. Colors alone do not prove polarity. Check D6 through the series resistor to DIN, not DOUT.
  2. Keep the power paths separate. The reported 5V/10A adapter feeds the strip directly; UNO remains USB powered, with common ground as the signal reference. Do not route LED current through UNO or a breadboard, or join the adapter’s +5V to UNO +5V. The reported red/white connections are not independently verified.
  3. Prepare this separate sketch. Install FastLED 3.10.3 in Arduino Library Manager and select UNO R4 WiFi. Open in its own LED_Only_Bench_v1 folder and verify. Save the running sketch; only upload if Gary chooses to replace the current board program.

EXACT EXPECTED BEHAVIOR

Dark, then a single moving pixel.

Clears the 35 addressed pixels, stays dark for one second, then moves one pixel every 200ms. One red pass, then green, then blue; repeats at brightness 16/255. All other addressed pixels remain off. No white pattern or fading tail.

Serial Monitor at 115200 baud shows pixel index and color pass. Scheduling uses millis(); each FastLED.show() briefly transmits a frame. If the count exceeds 35, additional pixels are not cleared or tested.
