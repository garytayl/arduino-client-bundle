# LED-only first bench test

Page: https://stairs.layerlane.studio/#led . Download: https://stairs.layerlane.studio/downloads/LED_Only_Bench_v1.ino .

UNO R4 WiFi, FastLED 3.10.3, D6, 35 addressed RGB pixels, GRB order, brightness 16/255, no dithering. Initial clear, 1s dark, then one primary-color pixel moves every 200ms: red pass, green pass, blue pass, repeat. No tail/white/sensors/Wi-Fi/motors. `millis()` schedules frames; `show()` itself briefly occupies the processor. Only 35 pixels are cleared, matching the approximate reported section count rather than the original firmware's LED count.

Uncompiled, not flashed and physically untested. No local Arduino CLI/IDE core or FastLED install was found in inspected standard locations. [FastLED 3.10.3 chipset definitions](https://github.com/FastLED/FastLED/blob/3.10.3/src/chipsets.h) provide the WS2812-family 800kHz profile and its [Renesas driver](https://github.com/FastLED/FastLED/blob/3.10.3/src/platforms/arm/renesas/clockless_arm_renesas.h) supports RA4M1. [Worldsemi's indexed WS2812E-V5 datasheet](https://www.world-semi.com/downloads/datasheets/zh-CN/ws2812e-2.1.pdf) describes 800kHz operation, but the full PDF could not be retrieved through the research tool and the strip's exact variant/timing/color order is not confirmed. WS2812B/GRB is a compatibility test, not a proven exact WS2812E controller selection.

Reported wiring: D6 via a series resistor in separate breadboard rows; standalone 5V/10A adapter direct to strip red/white; common GND via UNO rail; UNO/ToF USB powered. This report is not independent wiring or polarity verification. Gary now confirms the DIN label at the connected end; this is a user report, not an independent electrical inspection. With all power off, verify labeled DIN direction, 5V/GND polarity and resistor/data connection. Keep LED current out of UNO/breadboard, adapter +5V separate from UNO +5V, and a shared signal ground. Preserve the current sketch and choose any upload explicitly. No local Mac or hardware access is performed.
